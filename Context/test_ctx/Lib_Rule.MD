# Library Business Rules

This document describes the business rules currently modeled by the library test context.

The context model is maintained by `spec/js/dal.js`. The test behavior is generated by `spec/js/lib_stories.js`, and the REST calls and verification helpers are defined in `spec/js/interfaces.library.js`.

## Main Entities

### User

A user represents a library member.

Rules:

- A user can be created independently.
- A user can be deleted only when the user has no active loans and no active holds.
- If a user has an active loan, deleting that user is expected to fail with `400`.
- After a successful user deletion, the user should not appear in users, loans, or holds lists.
- Deleting a user that no longer exists is expected to fail with `404`.

Context queries:

- `User.All`
- `User.CanDelete`
- `User.HasLoan`

## Book

A book represents a library item.

Rules:

- A book can be created independently.
- A book can be deleted only when the book has no active loans and no active holds.
- After a successful book deletion, the book should not appear in books, loans, or holds lists.
- Deleting a book that no longer exists is expected to fail with `404`.

Context queries:

- `Book.All`
- `Book.CanDelete`

## UserBook

`UserBook` is the context relation between a user and a book.

For every existing user and every existing book, the DAL creates a `user-book` entity. This gives the stories a simple way to ask questions about valid user/book pairs.

Rules:

- When a new user is created, the DAL creates `user-book` rows for that user with all existing books.
- When a new book is created, the DAL creates `user-book` rows for that book with all existing users.
- When a user is deleted, all `user-book` rows for that user are removed.
- When a book is deleted, all `user-book` rows for that book are removed.

Context queries:

- `UserBook.All`
- `UserBook.CanCreateLoan`
- `UserBook.CannotCreateLoan`
- `UserBook.CanCreateHold`
- `UserBook.BookHasLoan`
- `UserBook.BookUserHasHold`

## Loans

A loan connects one user to one book.

Rules:

- A loan can be created only when the user has no active loan and the book has no active loan.
- A user cannot have more than one active loan.
- A book cannot have more than one active loan.
- A second successful loan creation for the same user or the same book is blocked while the original loan exists.
- If a loan already exists for the user or the book, trying to create another loan is expected to fail with `400`.
- A loan can be deleted when it exists.
- After a successful loan deletion, the loan should not appear in the loans list.
- Deleting a loan that no longer exists is expected to fail with `404`.

Context queries:

- `Loan.All`
- `UserBook.CanCreateLoan`
- `UserBook.CannotCreateLoan`
- `User.HasLoan`

Story behavior:

- `crud:Loans:create` creates valid loans from `UserBook.CanCreateLoan`.
- `verifyCannotCreateLoanForBusyUserOrBook` verifies that invalid loan creation fails with `400`.
- `blockDuplicateSuccessfulLoanCreation` blocks duplicate successful loan creation while the active loan still exists.
- `deleteLoan` deletes existing loans from `Loan.All`.

Trace format:

```text
Create a loan <loan-number> <user-id>/<book-id>
Delete a loan <loan-number> <user-id>/<book-id>
```

Example:

```text
Create a loan 609009 587/391
Delete a loan 609009 587/391
```

## Holds

A hold connects one user to one book request.

Rules:

- A hold can be created only when the book is not loaned.
- A hold can be created only when the same user/book pair does not already have an active hold.
- A user may have holds on more than one book.
- A book may have holds by more than one user, as long as the book is not loaned.
- A duplicate hold for the same user/book pair is expected to fail with `400`, even if the new hold has a different hold number.
- A hold on a loaned book is expected to fail with `400`.
- A hold can be deleted when it exists.
- After a successful hold deletion, the hold should not appear in the holds list.
- Deleting a hold that no longer exists is expected to fail with `404`.

Context queries:

- `Hold.All`
- `UserBook.CanCreateHold`
- `UserBook.BookHasLoan`
- `UserBook.BookUserHasHold`

Story behavior:

- `crud:Holds:linear:2` creates valid holds from `UserBook.CanCreateHold`.
- `verifyCannotCreateHoldForLoanedBook` verifies that hold creation on a loaned book fails with `400`.
- `verifyCannotCreateDuplicateHold` verifies that duplicate hold creation for the same user/book fails with `400`.
- `blockDuplicateSuccessfulHoldCreation` blocks duplicate successful hold creation while the active hold still exists.
- `deleteHold` deletes existing holds from `Hold.All`.

Trace format:

```text
Create a hold <hold-number> <user-id>/<book-id>
Delete a hold <hold-number> <user-id>/<book-id>
```

Example:

```text
Create a hold 640626 587/391
Delete a hold 640626 587/391
```

## Loan and Hold Relationship

Loans and holds are related through the book.

Rules:

- If a book has an active loan, creating a hold for that book is expected to fail with `400`.
- If a book has an active loan, the book cannot be deleted.
- If a user has an active loan, the user cannot be deleted.
- If a book has active holds, the book cannot be deleted.
- If a user has active holds, the user cannot be deleted.
- Deleting a user or book removes the matching context state for user-book rows, loans, and holds after a successful delete event.

## Context State Changes

The DAL updates the context only after events that are expected to succeed.

Rules:

- `POST` events update the context only when the event expects `201`.
- `POST` events expecting `400` or `404` are verification attempts and do not create context entities.
- `DELETE` events update the context only when the event expects `200`.
- `DELETE` events expecting `400` or `404` are verification attempts and do not remove context entities.

This prevents negative verification calls from corrupting the expected model.

## Current Important Assumptions

- The current loan rule is strict: one active loan per user and one active loan per book.
- The current hold rule is more flexible: a user can hold multiple different books, and a book can have holds from multiple different users, but the same user/book pair cannot have two active holds.
- Hold numbers are unique identifiers for hold deletion.
- Loan numbers are used for trace descriptions, while the loan identity in the SUT is the `userId/bookId` pair.
